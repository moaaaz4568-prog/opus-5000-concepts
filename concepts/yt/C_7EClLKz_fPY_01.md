# فحص توافر API قبل الأتمتة: اسأل «هل للبرنامج واجهة برمجة؟ وما الإجراءات المتاحة؟»

**التصنيف:** مفهوم — هندسة أتمتة عبر وكيل برمجي (مقطع ~277 كلمة عن هيكلة إجراءات الأتمتة).

**المصدر الرئيسي:** S_yt_7EClLKz_fPY_ar.

## ملخص
المشكلة: يمكنك «أتمتة كل شيء على التوالي»، لكن «إذا لم يكن لديّ رؤية، إذا لم يكن لديّ السياق — ما هي بالضبط الأتمتة — هذا صعب للغاية». الحل: هيكلة الإجراءات خطوة بخطوة، وفي كل خطوة فحص مسبق: «تحقق مما إذا كان لهذا البرنامج API»، لأنه «ماذا لو لم يكن لديه API؟ لن يتمكن Claude Code من التعامل معه أو التفاعل معه» — أي أن الوكيل لن يستطيع تنفيذ أفعاله. طريقة الفحص إن غاب API: السؤال خارجيًا (عبر ChatGPT): «هل لدى [البرنامج] API؟ وإذا نعم، ما الإجراءات التي يمكن اتخاذها من خلاله؟» — كإضافة جهات اتصال إلى HubSpot: الإنشاء، القراءة، التحديث، الحذف، جهات الاتصال، المؤسسات.

## مكونات المفهوم
1. السبق للسياق: قبل أي أتمتة، حدد «ما هي بالضبط الأتمتة» — بلا رؤية وسياق تفشل السلسلة كلها مهما تتابعت الخطوات.
2. بروتوكول الفحص لكل خطوة: هل هذا يحدث؟ هل هذا صحيح؟ وما ضمان البرمجة المستخدم؟ — تحقق من المستخدم في هذه المرحلة من العملية.
3. فحص التوافر: قبل الاعتماد على أداة، اسأل هل لها API؛ بلا API لا يستطيع Claude Code الأداء داخلها.
4. بروتوكول الاكتشاف عبر ChatGPT عند الشك: «هل لدى [البرنامج] API؟ وما هي الإجراءات التي يمكن اتخاذها من خلال هذا الـ API؟» — فتعرف ما يجب فعله وما لا يجب.
5. مثال تشغيلي: HubSpot — عمليات ممكنة: إنشاء، قراءة، تحديث، حذف، جهات اتصال، مؤسسات؛ تضيف اتصالًا فتسأل أولًا عن API والإجراءات المسموحة.

## الأخطاء القاتلة
| الخطأ | لماذا يقتل | البديل |
| --- | --- | --- |
| أتمتة كل شيء تسلسليًا دون سياق | «إذا لم يكن لديّ السياق، ما هي بالضبط الأتمتة — هذا صعب للغاية» | هيكلة الإجراءات وتحديد الأتمتة المطلوبة أولًا |
| افتراض أن كل برنامج له API | بلا API «لن يتمكن Claude Code من التعامل معه» وتتعطل الخطوة | فحص التوافر (أو السؤال عبر ChatGPT) قبل بناء الخطوة |
| اكتشاف إمكانيات الأداة وقت التنفيذ | تعرف النجاح متأخرًا بعد فشل السلسلة | سؤال «ما الإجراءات المتاحة عبر الـ API؟» مسبقًا (إنشاء/قراءة/تحديث/حذف...) |
